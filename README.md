# LinFW

TUI для управления правилами iptables. Команда `linfw`, мышь и клавиатура, правила переживают перезагрузку.

## Установка

```bash
curl -fsSL https://raw.githubusercontent.com/bolgov0zero/LinFW/main/install.sh | sudo bash
```

Если sudo не установлен, станьте root (`su -`) и запустите ту же команду без `sudo`:

```bash
curl -fsSL https://raw.githubusercontent.com/bolgov0zero/LinFW/main/install.sh | bash
```

Установщик очищает экран и показывает только шаги (со спиннером и галочкой, замечания жёлтым); весь вывод `apt`/`pip` идёт в лог, который показывается, только если шаг упал. `NO_COLOR=1` отключает цвета. Он:

- сначала **проверяет систему**: поддерживаются только **Debian и Ubuntu** (и производные: Mint, Raspberry Pi OS и т. п., то есть системы с `apt`). На любой другой установка останавливается с объяснением, ничего не меняя;
- ставит `python3`, `iptables`, `iptables-persistent` (правила переживают перезагрузку) и `ipset` с `ipset-persistent` (то же для адресных списков);
- кладёт LinFW в `/opt/linfw` (отдельный virtualenv) и создаёт команду `/usr/local/bin/linfw`.

Требуется Python 3.9+. Удаление: `sudo ./install.sh --uninstall` (правила iptables не трогаются).

## Запуск

```bash
linfw          # не root: перезапустится через sudo; если sudo нет — запускайте от root
linfw --demo   # тестовые правила в памяти, без root и iptables (можно и на macOS)
```

## Интерфейс

Тёмно-синее оформление с тонкими скруглёнными рамками. Сверху хлебные крошки (`iptables › INPUT`) и состояние автосохранения, под ними вкладки цепочек (INPUT / OUTPUT / FORWARD): число правил и политика по умолчанию (`INPUT  7  accept`). Дальше шкала долей пакетов по действиям (процент `drop`, число включённых правил, пакетов в секунду с мини-графиком) и две панели: «Цепочка» (сколько правил, включено, выключено, с журналом, политика) и «Пакеты» (accept / drop / reject с полосками и процентами, сколько отклонено). Ниже таблица правил:
`#`, `Pkts`, `chain`, `protocol`, `source`, `destination`, `port`, `action`; номер выбранной строки написан в нижней рамке. Action окрашен: **accept** — зелёный, **drop** — красный, **reject** — оранжевый. Под таблицей — понятное описание выбранного правила (что делает, сколько пакетов и байт) и его запись для iptables. Внизу строка клавиш (каждая подсказка кликабельна, неподходящие приглушены, а «выкл» сам превращается во «вкл») и строка состояния. В пустой цепочке вместо таблицы показана подсказка. На низком терминале (меньше 32 строк) шкала и панели скрываются, чтобы таблице хватило места. Диалоги в розовой рамке: название вверху, подсказки клавиш в нижней границе; `?` показывает все клавиши. Цвета берутся из одной темы `linfw`; другую тему можно выбрать через палитру команд (`Ctrl+P`).

| Подсказка | Клавиши | Действие |
|---|---|---|
| Добавить | `F1`, `a` | модальное окно: chain, protocol, action выбираются из списка, source / destination / port вводятся |
| Изменить | двойной клик, `Enter`, `e` | то же окно, что и «Добавить», с текущими значениями; позиция и состояние вкл/выкл сохраняются, цепочку менять нельзя, счётчик Pkts начинается заново. Правила с условиями, которых нет в окне (`+` в колонке port), не редактируются |
| Удалить | `F2`, `Delete`, `x` | удаление с подтверждением |
| Шаблон | `F3`, `t` | SSH (22), ICMP, HTTP/HTTPS (80, 443) — открыть для всех |
| ▲ | `F4`, `u` | поднять правило |
| ▼ | `F5`, `d` | опустить правило |
| Выключить / включить | `F6`, `Space` | отключить правило, не удаляя его; оно остаётся на своём месте |
| Журнал | `F7`, `j` | общий журнал срабатываний (см. ниже); `Esc`, `F7` или кнопка «К правилам» — назад |
| Списки | `F8`, `l` | адресные списки (см. ниже) |
| Ещё | `?` | список всех клавиш |
| Выход | `F10`, `Esc`, `q` | закрыть LinFW; правила остаются как есть |

Также: `←` `→` — вкладки, `↑` `↓` — строки, `r` — обновить. Все кнопки, вкладки, строки и списки работают мышью, таблица прокручивается колесом. Счётчики `Pkts` обновляются каждые 2 секунды.

## Адресные списки

Окно **«Списки»** (`F8`): слева списки (название, число адресов, в скольких правилах используется), справа адреса выбранного списка. `N` — создать список, `A` — добавить адреса (вставкой: по одному в строке или через пробел/запятую; IPv4-адреса и сети вроде `10.0.0.0/24`), `X` — удалить список, `Delete` — удалить адрес. Список, который используется в правилах, удалить нельзя: окно покажет, в каких именно.

В окне правила рядом с **Source** и **Destination** есть кнопка **«Список ▾»**: она открывает перечень названий, выбор подставляет `@имя` в поле (его можно и набрать руками). В таблице такое условие выглядит как `@имя`, а в описании под таблицей — «от списка «имя»». Состав списка меняется на лету и сразу действует во всех правилах, где он используется, сами правила при этом не переписываются.

Как это устроено: список `office` — это набор ipset `lf_office` (`hash:net`), правило ссылается на него условием `-m set --match-set lf_office src|dst`. Список **сохраняется и восстанавливается при загрузке раньше правил** плагином `ipset-persistent` (`10-ipset`, он стартует до `15-ip4tables`), поэтому правило со ссылкой на список не может подняться без него. Без пакета `ipset-persistent` окно предупредит, что списки пропадут после перезагрузки.

- Только IPv4, без отрицания («все, кроме списка») и сроков жизни адресов.
- Нужны пакет `ipset` и модули ядра `ip_set`, `ip_set_hash_net` (в контейнере их, возможно, придётся загрузить на хосте: `modprobe ip_set ip_set_hash_net`). Если списки недоступны, окно и кнопка выбора покажут причину.
- Чужие наборы ipset (fail2ban и др.) LinFW не трогает: свои наборы он называет с префиксом `lf_`. Правила, использующие чужой набор, показываются как есть (с «+» в колонке port).

## Журнал срабатываний

В окне «Добавить» / «Изменить» есть флажок **Journal** (по умолчанию выключен). У правила с включённым журналом в колонке action стоит `●`. Кнопка **Журнал** (F7) открывает общую таблицу срабатываний: время, цепочка, протокол, откуда, куда, порт и действие, новые записи сверху. Два независимых фильтра работают вместе: по цепочке (**Все / INPUT / OUTPUT / FORWARD**, или `←` `→`) и по действию (**accept / drop / reject**, или `a` `d` `r`; можно включить несколько, ни одного = все). **К правилам** (`Esc`) возвращает к правилам. Журнал — **снимок**: он читается при открытии и по кнопке **Обновить** (`F5`) и больше **сам не меняется**, новые записи не появляются, пока вы его смотрите. Время снимка написано в строке под таблицей. Смена фильтров ничего не перечитывает, а только пересортировывает загруженное (до 50 000 последних записей), так что новые записи не появятся и от неё.

Как это устроено: перед правилом ставится скрытое парное правило `NFLOG` с теми же условиями (оно не показывается и двигается, выключается и удаляется вместе с основным). Пакеты уходят в netlink-группу 40, их принимает служба **`linfw-logd`** (ставится установщиком, `systemctl status linfw-logd`) и пишет в `/var/log/linfw/hits-ГГГГ-ММ-ДД.log` — по файлу на день. **Записи хранятся 30 дней**, файлы старше удаляются службой. В таблице показываются последние 5000 записей (или последние 5000 выбранной цепочки). Правила от ранних версий, которые писали через `LOG` в журнал ядра, при запуске переносятся на NFLOG автоматически; их старые записи подтягиваются из `journalctl -k` / `kern.log`.

Почему не `LOG`: он пишет в буфер ядра, а контейнеры (LXC, OpenVZ) его не читают — `dmesg` там отвечает `Operation not permitted`. NFLOG работает и в контейнерах.

- Запись ограничена **10 в минуту на правило** (`-m limit`), чтобы журнал не заполнил диск (не больше ~150 тыс. записей, около 10–15 МБ, в сутки на 10 правил), поэтому в нём выборка, а не каждый пакет. Точное число срабатываний — колонка **Pkts**.
- Нужны модули ядра `xt_NFLOG` и `nfnetlink_log` (в контейнере их загружают на хосте: `modprobe nfnetlink_log`).
- Нужен systemd; без него запускайте `linfw --logd` сами.
- Если записей нет, под таблицей написано почему: правило не включено, ещё не срабатывало или служба не работает.

## Счётчики Pkts не сбрасываются

Счётчики iptables живут в ядре и обнуляются при перезагрузке, при перезагрузке правил другой программой (`netfilter-persistent reload`, `iptables-restore`, `iptables -Z`), раньше — и при редактировании правила. LinFW ведёт собственные **накопленные итоги** в `/var/lib/linfw/counters.json`: в таблице показано всё, что правило насчитало с момента, как LinFW его увидел, независимо от сбросов, точным числом.

- Служба `linfw-logd` каждые 5 секунд добавляет приращение счётчиков в итог (и ещё раз при остановке), поэтому итог копится, даже когда LinFW закрыт. Открытый LinFW делает то же раз в 2 секунды.
- Правило узнаётся по цепочке и своему определению, поэтому итог сохраняется при перемещении, выключении/включении, перезагрузке и **редактировании** (итог переходит к новому виду правила).
- Итог сбрасывается только если вы **удалили** правило (или правило пропало больше чем на 30 дней).
- Потерять можно лишь приращение между последней выборкой и внезапным обрывом (выключение питания): не больше 5 секунд.
- Без службы (нет systemd) итоги копятся только пока открыт LinFW; после перезагрузки счётчики в этот промежуток не попадают.

## Базовые правила

При установке (и при каждом запуске LinFW, если их нет) на самый верх цепочек ставятся правила, без которых `DROP` обрывает связь:

| Цепочка | Правила |
|---|---|
| INPUT, OUTPUT | `lo` — loopback; `RELATED,ESTABLISHED` — ответы на соединения, которые вы сами начали |
| FORWARD | `RELATED,ESTABLISHED` |

Они не показываются в таблице (нумерация `#` идёт без них), не выключаются, не удаляются и не двигаются, а правила нельзя поднять выше них. Если их удалить или сместить снаружи, LinFW вернёт их при следующем обновлении. Каждое такое правило помечено комментарием `linfw:base:*`.

Следствие: `DROP` для конкретного адреса не разорвёт **уже установленные** соединения с ним — запретятся только новые.
Убрать базовые правила: `sudo linfw --remove-base` (при `./install.sh --uninstall` это делается само); поставить заново: `sudo linfw --apply-base`.

## Как это работает

- **Порядок.** Новые правила (и из окна «Добавить», и из шаблонов) всегда добавляются в конец цепочки. Если в конце уже стоит `DROP` на всё, поднимите новое правило выше кнопкой F4.
- **Выключение.** В iptables нет флага «выключено». Выключенное правило остаётся на месте со всеми условиями, но его цель заменяется переходом в пустую цепочку `LINFW_OFF_<ACTION>`: пакет возвращается и проверяется следующим правилом. Состояние хранится в самом iptables и сохраняется вместе с остальными правилами. Выключить можно правила с действием accept / drop / reject; у `REJECT` после повторного включения восстанавливается `--reject-with` по умолчанию.
- **Перемещение.** Копия вставляется на новое место, и только потом удаляется оригинал — в цепочке нет момента без правила. Счётчики сохраняются.
- **Сохранение.** После каждого изменения выполняется сохранение (`netfilter-persistent save` или запись в файл дистрибутива).
- **Параллельные правки.** Перед каждым изменением цепочка перечитывается; если правило сдвинулось снаружи, действие отменяется.
- Правила с условиями, для которых нет колонки (`-i`, `-m state` …), показываются как есть; в колонке port у них стоит `+`, а полная запись — в строке под таблицей.
- Поддерживается таблица `filter` и IPv4.

> ⚠️ Не блокируйте себя: при работе по SSH не ставьте `DROP` на INPUT до того, как разрешён порт 22 (шаблон F3).
